# /supabase-sync — Supabase 스키마 검증 스킬

코드에서 참조하는 Supabase 테이블/컬럼이 실제 스키마와 일치하는지 검증한다.

## 사용법

- `/supabase-sync` — 전체 검증
- `/supabase-sync {도메인}` — 특정 도메인만 검증

## 인자

`$ARGUMENTS`가 있으면 해당 도메인만, 없으면 전체 도메인 검증.

---

## 실행 절차

### 1. 코드에서 테이블/컬럼 참조 수집

아래 패턴으로 코드를 검색한다:

- `app/` 디렉토리 내 모든 `.js`, `.jsx` 파일
- 검색 패턴:
  - `.from('테이블명')` — Supabase 쿼리의 테이블 참조
  - `.select('컬럼목록')` — 컬럼 참조
  - `.insert({...})` — insert 시 사용하는 컬럼
  - `.update({...})` — update 시 사용하는 컬럼
  - `.eq('컬럼', 값)` — 필터 조건의 컬럼
  - `.order('컬럼')` — 정렬 컬럼

각 파일별로 참조하는 테이블명과 컬럼명을 추출하여 목록화한다.

### 2. SPEC.md에서 스키마 정의 수집

각 도메인의 `skills/domain-driven/bounded-contexts/{도메인}/specs/SPEC.md`에서 테이블 스키마 정의를 읽는다.
- 테이블명, 컬럼명, 타입 정보를 추출

### 3. 교차 검증

| 검증 항목 | 설명 |
|---|---|
| 테이블 존재 여부 | 코드에서 참조하는 테이블이 SPEC에 정의되어 있는가 |
| 컬럼 존재 여부 | 코드에서 참조하는 컬럼이 해당 테이블 SPEC에 있는가 |
| 컬럼명 오타 감지 | 유사한 컬럼명이 있는데 정확히 매칭되지 않는 경우 |
| 미사용 컬럼 | SPEC에 정의되어 있지만 코드에서 참조하지 않는 컬럼 |

### 4. 결과 출력

```
## Supabase 스키마 검증 결과

### 일치 항목
- restaurants.name — OK
- restaurants.address — OK
- ...

### 불일치 항목 (수정 필요)
- reviews.taste_score — 코드에서 참조하지만 SPEC에 없음
- reviews.visual → SPEC에는 `visual_score`로 정의됨 (오타 의심)

### 미사용 컬럼 (참고)
- restaurants.longitude — SPEC에 정의되어 있지만 코드에서 미참조

### 요약
- 총 테이블: N개, 총 컬럼: N개
- 일치: N개, 불일치: N개, 미사용: N개
```

---

## 에러 처리

- SPEC.md에 스키마 정의가 없는 도메인은 건너뛰고 경고 표시
- Repository 파일이 아직 없는 도메인은 "미구현" 표시
- `app/` 디렉토리가 없으면 에러

## 주의사항

- 이 스킬은 코드 ↔ SPEC 간 검증이며, 실제 Supabase 인스턴스에 접속하지 않음
- 실제 DB 스키마와 SPEC이 다를 수 있으므로, SPEC을 신뢰 기준으로 사용
- RLS 정책은 검증 범위에 포함하지 않음
