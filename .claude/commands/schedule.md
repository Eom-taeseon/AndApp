# /schedule — 개발 일정 모니터링 스킬

현재 개발 일정의 진행 상태를 분석하고, 지연/리스크를 감지하여 보고한다.

## 사용법

- `/schedule` — 전체 일정 현황 보고
- `/schedule {phase번호}` — 특정 Phase 상세 분석

## 인자

`$ARGUMENTS`가 있으면 해당 Phase만, 없으면 전체 현황.

---

## 실행 절차

### 1. 데이터 수집

다음 소스에서 정보를 수집한다:

| 소스 | 수집 내용 |
|---|---|
| `DEVELOPMENT_SCHEDULE.md` | Phase별 기간, 작업 목록, 체크 상태 |
| `git branch -a` | 현재 존재하는 feature 브랜치 |
| `git log --oneline` | 최근 커밋 활동 |
| `git log --since="{Phase 시작일}"` | Phase 기간 내 커밋 수 |
| 오늘 날짜 | 남은 일수 계산 |

### 2. Phase별 진행률 계산

각 Phase에 대해:
- **작업 완료율**: `[x]` 체크된 항목 / 전체 항목 × 100%
- **일정 소화율**: (오늘 - 시작일) / (종료일 - 시작일) × 100%
- **건강도 판정**:
  - 🟢 **정상**: 작업 완료율 >= 일정 소화율
  - 🟡 **주의**: 작업 완료율이 일정 소화율보다 20%p 이하로 뒤처짐
  - 🔴 **지연**: 작업 완료율이 일정 소화율보다 20%p 초과로 뒤처짐
  - ⬜ **대기**: 아직 시작 전
  - ✅ **완료**: 모든 항목 체크됨

### 3. 리스크 감지

다음 상황을 자동 감지하여 경고:

| 리스크 | 조건 | 심각도 |
|---|---|---|
| **마감 임박** | 종료일까지 1일 이하 남음 + 미완료 항목 존재 | 🔴 |
| **진행 정체** | 최근 24시간 커밋 없음 + 진행 중 Phase | 🟡 |
| **브랜치 미생성** | Phase 시작일 지남 + feature 브랜치 없음 | 🔴 |
| **일정 겹침** | 이전 Phase 미완료 + 다음 Phase 시작일 도래 | 🟡 |
| **스코프 초과** | 작업 항목이 원래보다 증가함 (git diff로 감지) | 🟡 |

### 4. 결과 출력

```
## 📊 폰슐랭 일정 현황 — {오늘 날짜}

### 전체 타임라인

Phase 1 ████████░░ 80%  🟢 정상  (3/14 마감, 1일 남음)
Phase 2 ░░░░░░░░░░  0%  ⬜ 대기  (3/15 시작)
Phase 3 ░░░░░░░░░░  0%  ⬜ 대기  (3/19 시작)
Phase 4 ░░░░░░░░░░  0%  ⬜ 대기  (3/26 시작)

### Phase 1 — Identity (인증) 상세

| 작업 | 상태 | 비고 |
|---|---|---|
| LoginForm.jsx | ✅ 완료 | |
| SignupForm.jsx | ✅ 완료 | |
| AuthContext | ✅ 완료 | |
| AuthPage 라우팅 | 🔲 미완료 | ← 남은 작업 |
| dev PR 생성 | 🔲 미완료 | |

- 완료: 3/5 (60%)
- 일정 소화: 75% (4일 중 3일 경과)
- 건강도: 🟡 주의

### ⚠️ 리스크 알림

1. 🔴 **마감 임박**: Phase 1 마감까지 1일, 미완료 2건
2. 🟡 **일정 여유 부족**: Phase 2 시작(3/15)까지 1일, Phase 1 완료 필요

### 💡 권장 조치

1. AuthPage 라우팅 우선 완료 → `/feature done`으로 PR 생성
2. Phase 1 완료가 지연되면 Phase 2 시작일 조정 고려
```

---

## Phase 상세 모드 (`/schedule {N}`)

특정 Phase를 지정하면 추가로:
- 해당 Phase의 모든 커밋 목록
- 일별 커밋 분포 (어느 날 작업량이 많았는지)
- 각 작업 항목별 관련 커밋 매핑 (커밋 메시지 기반 추론)
- 해당 도메인 LOG.md의 최신 기록

---

## 에러 처리

- `DEVELOPMENT_SCHEDULE.md`가 없으면: 에러
- Phase 번호가 범위 밖이면: 경고 후 전체 현황 표시
- git 이력이 없으면: 커밋 관련 분석 생략

## 주의사항

- 이 스킬은 읽기 전용 — 일정이나 코드를 수정하지 않음
- 작업 완료율은 `DEVELOPMENT_SCHEDULE.md`의 체크박스 기준이므로, 체크를 안 했으면 실제 완료여도 미완료로 표시됨
- `/feature done`이 체크박스를 업데이트하므로, 해당 스킬과 함께 사용하면 정확도가 높아짐
